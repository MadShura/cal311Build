# forPlayGameWeb

本项目用于计算 三国志11初始人物建造，计算出最短时间内建造完毕并且是最多经济的建造方案

## 架构为什么是脚本工具而不是 PWA

纯计算工具，输入参数 → 输出最优方案，无本地文件依赖，**不适合未来改造为 PWA** 计算容易爆栈


# 311build — 三国志11 建设方案最优计算器

## 项目概述

计算限定时间内，给定固定武将组合，算出最多经济的建设方案。核心是一个带剪枝的搜索算法，遍历武将组合与建筑选择的所有可能，找到最优解。

## 用法

```bash
pnpm 311b
```

输出结果写入 `_gen-result.json` 和 `result.log`。

## 文件结构

- `index.ts`：主入口，搜索主流程（执行操作、过回合、记录最终结果），剪枝判定统一调用 `prune.ts`
- `prune.ts`：剪枝逻辑统一存放处（对应 README `## 剪枝策略` 整节）——核心二维比较 + 操作顺序剪枝、回合收入剪枝、建筑完不成剪枝、行动力不符合 / 武将不空闲 / 回合超出等纯判定剪枝，以及缓存声明与写出
- `game-logic.ts`：游戏规则计算（月收入、巡查、建造组合、缓存键生成等）
- `data.ts`：武将数据、初始状态、常量定义
- `types.ts`：类型定义（stat、Moving、ActionChoice、TurnAction 等）
- `console.ts`：输出与记录工具（初始化、写文件、剪枝计数）
- `_gen-result.json` / `result.log`：计算结果输出
- `output/`：中间输出目录（各回合结束缓存、剪枝统计等）


## 剪枝策略

键设置为 回合 + 建造情况 + 人物空闲情况。值是二维数组 [[治安,金钱]]
缓存命中优化：行动缓存的市场值如 [0,3,0] 序列化为 [0,0,3] 增加缓存命中率
剪枝对比：同样的键：

1 治安相同 金钱相同 剪枝
2 治安相同 金钱少   剪枝
3 治安相同 金钱多   不剪枝 删差缓存
4 治安更少 金钱相同 剪枝
5 治安更多 金钱相同 不剪枝 删差缓存
6 治安更多 金钱更少 不剪枝 保留缓存
7 治安更少 金钱更多 不剪枝 保留缓存
8 治安更少 金钱更少 剪枝
9 治安更多 金钱更多 不剪枝 删差缓存

**操作顺序剪枝**：一回合多个操作的排列等价（A 做市场 B 做市场 = B 做市场 A 做市场），通过状态缓存去重。对应 1

## **回合收入剪枝**：
比较 3/6/9/12 回合收入，12 回合固定，只能剪枝到 7 回合开始处（因最小建造时间影响后续回合） 需要知道更好的结果 回来推算 这不是上面的逻辑


## 建筑完不成剪枝
当操作大于最小建筑时间或小于最小巡查值时，才考虑"什么都不做"

## 以前推翻的剪枝
不需要记录各个状态的行动力： 比如 
6 回合,治安92 市场[0,4,6,6]造币厂[3]巡查[0]伦直3公孙度95公孙康95公孙恭0公孙渊6卑衍6徐荣3杨祚4贾范4: 2393 行动力 100
6 回合,治安92 市场[0,4,6,6]造币厂[3]巡查[0]伦直3公孙度95公孙康95公孙恭0公孙渊6卑衍6徐荣3杨祚4贾范4: 2393 行动力 80
因为行动是可以选什么都不做的，所以这样很明显就是 某个节点是前面 2回合 什么都不做 ，某个是 1 回合 什么都不做

### 执行流程

1. 先做必做动作
2. 判断是否还有行动力
3. 根据所剩行动力获取所有可能操作
4. 执行操作，判断是否还有行动力
5. 无行动力就过回合
6. 当某个设计做完所有建筑，根据建筑完成情况结算

## 当前问题

武将组合爆炸：11 个武将，每行动选 1-3 人，组合数 = C(11,1)+C(11,2)+C(11,3) = 231 种，每种组合可做多种建筑，分支因子巨大。
